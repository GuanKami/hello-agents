# ReAct：推理与行动交替的 Agent 模式

ReAct 是 Reasoning and Acting 的缩写。它把大语言模型的分析过程和外部行动结合起来：模型先根据用户问题决定下一步行动，再调用工具获得观察结果，最后根据观察结果继续处理问题。

## 基本执行循环

一个最小的 ReAct 循环通常包含以下步骤：

1. 用户提出问题。
2. 模型读取当前对话和可用工具，决定是否需要调用工具。
3. 如果需要工具，模型生成结构化的 tool call，例如工具名称和参数。
4. Agent 执行工具，并把工具返回值包装成 ToolMessage。
5. 模型读取 ToolMessage，判断信息是否足够；如果不够，可以继续调用工具。
6. 当模型不再生成 tool call 时，返回最终的自然语言回答。

例如，用户询问北京天气时，模型可以生成 `get_weather(city="北京")`。天气工具返回实时天气后，模型再根据这个观察结果组织最终回答。模型产生工具调用只是“行动意图”，并不代表工具已经成功执行；只有工具返回 ToolMessage 后，Agent 才获得了真实的观察结果。

## ReAct 与普通聊天的区别

普通聊天通常是“用户问题 -> 模型回答”这一条路径。ReAct 则允许模型在回答过程中访问外部工具，例如计算器、搜索服务、数据库和天气接口。因此，ReAct 可以处理模型参数中没有的实时信息，也可以执行需要外部系统参与的任务。

在 LangGraph 中，ReAct 循环可以表示为：

```text
用户消息 -> 模型节点
              |
              +-- 有 tool_calls -> 工具节点 -> 模型节点
              |
              +-- 没有 tool_calls -> 结束
```

## ReAct 的优点和限制

ReAct 的优点是结构直观，模型可以根据工具结果动态调整下一步行动，适合搜索、计算和多步任务。它的限制是模型可能选择错误的工具、生成错误参数，或者在工具调用和模型调用之间循环太多次。因此，实际系统通常还需要权限控制、异常处理、最大循环次数、超时和人工审批。

ReAct 关注的是 Agent 的决策循环；StateGraph 关注的是如何把这个循环中的状态、节点和路由显式组织起来。两者不是互相替代的概念，StateGraph 可以用来实现和观察 ReAct 流程。
